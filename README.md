Репозиторий представляет собой набор утилит и клиент-серверных приложений, демонстрирующих работу с POSIX API. Все проекты собираются через `Makefile` и проверены на отсутствие утечек памяти с помощью `Valgrind`.

## 📌 Архитектура и реализованные механизмы

### 1. Многопроцессный UDP-сервер (Lab 3)
Сетевой сервис, способный обрабатывать множество клиентских UDP-запросов параллельно, с демонизацией и безопасным сбором метрик.
* **Networking:** Работа с сокетами (AF_INET, SOCK_DGRAM), обработка таймаутов (`SO_RCVTIMEO`).
* **Multiprocessing:** Модель *Process-per-request* (`fork()`).
* **Daemonization:** Корректная отвязка от терминала (двойной `fork`, `setsid`, перенаправление потоков в `/dev/null`).
* **IPC & Concurrency:** Безопасный сбор статистики между процессами с использованием анонимной разделяемой памяти (`mmap`) и атомарных переменных (`stdatomic.h`) без применения ресурсоемких мьютексов.
* **Сигналы:** Асинхронная обработка `SIGCHLD` (с `waitpid WNOHANG`) для сборки зомби-процессов, перехват `SIGUSR1`, `SIGINT`, `SIGTERM`.

### 2. Динамически загружаемые плагины (Lab 2)
Архитектура расширяемого приложения, где логика обработки данных делегируется внешним `.so` библиотекам.
* **API:** Использование `dlopen`, `dlsym`, `dlclose`.
* **Data Processing:** Поиск бинарных последовательностей IPv4-адресов в больших файлах с учетом сетевого порядка байт (Big-Endian / Little-Endian) через `__builtin_bswap32`.

### 3. Файловые системы и утилиты (Lab 1)
Рекурсивный обход файловых систем с использованием `ftw()`.
* Безопасная обработка прав доступа и ошибок (символические ссылки, запрещенные директории).
* Парсинг сложных аргументов командной строки через `getopt_long()`.
